# Project Context

## Scope
Mobile app ("Daybook"): 4 bottom-tab research app — Markets, Portfolio, Watchlist, Manage — plus a Calendar quick-link from the masthead. **Now a real installable PWA**, not just a mockup: live at https://theotverner.github.io/daybook-research-app/, installable via Safari → Share → Add to Home Screen on iPhone. News (now with real, actually-toggleable sources), portfolio/watchlist prices + day change, "why is it moving," real podcast episodes (via Apple Podcasts), the Calendar's earnings dates, and push notifications for upcoming earnings are all real — see Hosting / infrastructure for the backend details and exactly what Theo still needs to set up (several pieces need one-time Cloudflare dashboard configuration that can't be done from here). Spotify OAuth is built but **pending Theo registering a Spotify Developer app** (blocked externally — Spotify has new app creation on hold platform-wide) — see that section.

**Personal use only.** Theo confirmed this app is for himself and will not be published/distributed to anyone else. This meaningfully changes the risk profile: no app-store review process, no multi-user privacy law exposure (GDPR/CCPA etc. are triggered by processing *other people's* data, not your own), no need to worry about terms-of-service clauses aimed at commercial/public redistribution. Don't over-apply general regulatory caution that's really aimed at public products — but revisit this if Theo ever considers sharing or publishing it.

## Hosting / infrastructure
- **Repo**: github.com/TheoTVerner/daybook-research-app (public, main branch, served via GitHub Pages from branch root)
- **Live URL**: https://theotverner.github.io/daybook-research-app/
- **Local project folder**: `~/Desktop/Theo's Research App` — this *is* the git repo; working directly in it pushes straight to the live site (`git push` after committing updates to main)
- **SSH auth**: a dedicated deploy key was generated at `~/.ssh/id_ed25519_daybook`, registered in `~/.ssh/config` for github.com, and added to macOS Keychain — the public half is on Theo's GitHub account's SSH keys. No GitHub CLI (`gh`) or Homebrew installed on this Mac; Xcode Command Line Tools were installed mid-session to get `git` working.
- App structure: `index.html` / `styles.css` / `app.js` (plain, no build step, no framework) + `manifest.json` + `sw.js` (basic app-shell service worker) + `icons/` (generated locally via Pillow, not hand-designed).
- To ship an update: edit the files, `git add -A && git commit -m "..." && git push` from the project folder — GitHub Pages rebuilds automatically in under a minute, and the installed home-screen app picks up changes next time Theo opens it (no reinstall needed). Note GitHub Pages serves everything with `Cache-Control: max-age=600` — when verifying a just-shipped change, bypass with a cache-busting query string (`?t=...`) rather than assuming it's broken.
- **Backend**: one Cloudflare Worker at `worker/news-proxy.js` in the repo, deployed manually (Cloudflare account under Theo's login, Worker named `daybook-research`, URL `https://daybook-research.ttverner.workers.dev/`). Routes in the same Worker:
  - `GET /?sources=nyt,marketwatch,cnbc,bloomberg,ft` — real news from NYT, MarketWatch, CNBC, Bloomberg, and Financial Times RSS, fetched server-side (CORS blocks browsers from doing this directly). The `sources` param is optional (omit for all); the client (Manage > Connectors) persists which are enabled in `localStorage` and the toggles actually work — unlike most of this app's other cosmetic connector toggles, these 5 genuinely change what gets fetched. Results are round-robin'd by source (each source's most-recent, then 2nd-most-recent, etc., sorted by recency within each round) rather than a flat global sort — a prolific source like Bloomberg would otherwise crowd the others out of the top N. Don't assume feeds list newest-first in document order: Bloomberg's actually lists oldest-first, the opposite of the RSS norm, so each source's items get explicitly sorted by date before interleaving.
  - `GET /quotes?symbols=AAPL,MSFT` — real price + day change via Finnhub's free tier (needs the Cloudflare secret `FINNHUB_API_KEY`, a free key from finnhub.io, set in Worker Settings > Variables and Secrets).
  - `GET /explain?symbol=NVDA&name=Nvidia` — a "why is it moving" summary via **Cloudflare Workers AI** (free tier, needs an `AI` binding added in Worker Settings > Bindings — no separate account, it's built into Cloudflare). Only summarizes when real headlines actually mention the company; otherwise says so rather than letting the model invent a reason. Model used: `@cf/meta/llama-3.2-3b-instruct` (Cloudflare's catalog specifically calls this one out as suited to summarization). **Note**: Workers AI model IDs get deprecated over time (already hit this once — `llama-3.1-8b-instruct` was deprecated 2026-05-30) — if `/explain` ever silently falls back to "couldn't reach the summarizer," check the model ID against Cloudflare's current catalog (developers.cloudflare.com/workers-ai/models/) before assuming it's a code bug.
  - `GET /quotes` also fetches each symbol's real company name via Finnhub's `profile2` endpoint. Known gap: `profile2` doesn't cover ETFs/mutual funds well — VOO's name comes back null (price still works), and FXAIX returns null entirely (Finnhub's free-tier quote endpoint doesn't cover mutual fund NAV pricing at all, so FXAIX silently keeps showing its original hardcoded mock price). A mutual-fund-specific data source (e.g. Alpha Vantage covers some funds) would be the fix if that's worth doing.
  - `GET /earnings?symbols=AAPL,MSFT` — each symbol's next real earnings-call date via Finnhub's earnings calendar endpoint, scoped to a ~5-month forward window (quarterly cadence reliably catches the next one). Powers the Calendar tab, which is now fully dynamic: `buildCalendar()` re-fetches every time a ticker is added or removed from Portfolio/Watchlist (via the add form, watchlist remove button, or Remove from Portfolio/Watchlist in the detail overlay) — never a fixed/hardcoded ticker list.
  - `GET /company-news?symbols=AAPL,MSFT` — real per-company articles via Finnhub's `company-news` endpoint (last 10 days, same Finnhub key already used elsewhere, no new signup). This is now the **primary** news source for the Portfolio and Watchlist tabs (`loadCompanyNews()` in app.js), with the old general-pool name-matching (`renderFilteredStories`/`NAME_HINTS`) kept only as a fallback when Finnhub returns nothing for a symbol. Meaningfully better coverage than the general NYT/MarketWatch/CNBC/Bloomberg/FT pool for anything beyond mega-caps, since those 5 outlets rarely write about smaller names at all. `/explain` ("why is it moving") also tries this same per-company pool first before falling back to the general-pool match, for the same reason.
  - `GET /candles?symbol=AAPL&range=1D|5D|3M|6M|1Y|ALL` — historical close prices powering the stock detail page's chart. **Uses Twelve Data, not Finnhub** — Finnhub's free tier doesn't include historical candles at all (confirmed via Finnhub's own docs marking `/stock/candle` Premium, and independent reports of free keys getting a 403). Needs the Cloudflare secret `TWELVEDATA_API_KEY` (free key from twelvedata.com — **Theo still needs to sign up and set this one**; nothing chart-related will load until it's set). Twelve Data's free Basic plan is 800 requests/day, 8/min, which comfortably covers one person's chart views. Range → interval mapping lives in `CANDLE_RANGE_CONFIG` in the Worker (1D=5min bars, 5D=30min, 3M/6M/1Y=daily, ALL=weekly).
  - `POST /spotify/token` {code, redirect_uri} and `GET /spotify/shows?refresh_token=...` — real Spotify OAuth. **Not live yet** — needs a Spotify Developer app registered at developer.spotify.com/dashboard, with its exact redirect URI set to `https://theotverner.github.io/daybook-research-app/`. Once registered: give Claude the Client ID (not secret, safe to share — it needs updating in both `worker/news-proxy.js`'s `SPOTIFY_CLIENT_ID` constant and `app.js`'s `SPOTIFY_CLIENT_ID` constant, currently both placeholder strings), and set the Client Secret as a new Cloudflare secret named `SPOTIFY_CLIENT_SECRET` (Theo does this directly in the dashboard, never shared in chat — same pattern as `FINNHUB_API_KEY`). Flow: tapping Connect on the Spotify connector card sends the browser to Spotify's real login/consent screen (scope `user-library-read`), Spotify redirects back with a code, the Worker exchanges it for tokens, and the refresh token is stored in the browser's `localStorage` (key `daybook_spotify_refresh_token`) so Theo doesn't have to re-login each time. Once connected, real cover art + latest-episode titles replace the placeholder monogram cards (this app isn't sandboxed like an Artifact, so real `<img>` tags from Spotify's CDN work fine, no CSP restriction).
  - Podcasts: latest real episode for 7 curated shows, via **Apple's iTunes lookup API** (`itunes.apple.com/lookup?id=<collectionId>&entity=podcastEpisode`), not by parsing each show's raw RSS. This was a deliberate fix: several shows' RSS `<link>` tag pointed at a generic publisher/company webpage instead of anything podcast-related, which is what Theo was actually seeing when tapping a card. Apple's lookup API gives a genuine `podcasts.apple.com` episode deep link directly, plus clean artwork/title/date, no XML parsing needed. **Fetched client-side from `app.js` (`PODCAST_SHOWS` + `fetchApplePodcastEpisode()`), not through the Worker.** There used to be a `GET /podcasts` Worker route doing this same lookup server-side; it was removed because Apple's endpoint consistently returned `403` to Cloudflare Workers' shared egress IPs (confirmed: identical request worked fine from a plain curl off-Cloudflare). Apple's endpoint also sends `access-control-allow-origin: *`, which is the tell that it's meant to be called directly from a browser rather than proxied — so this is the correct fix, not a workaround. **Lesson for future server-side fetches**: if a third-party API 403s only from the Worker but works identically from a local curl, suspect IP-based blocking of Cloudflare's shared ranges before anything else (headers, auth, etc.) — check if the API sends CORS headers, and if so, move the fetch client-side instead of trying to spoof your way past it from the Worker.
  - `POST /push/subscribe` `{subscription, symbols}`, `POST /push/unsubscribe` `{endpoint}`, `POST /push/test` — real Web Push for earnings reminders (Manage > Notifications > Earnings Reminders). Needs: KV namespace bound as `PUSH_SUBS` (Settings > Bindings > KV Namespace), and the Cloudflare secret `VAPID_PRIVATE_KEY`. The matching `VAPID_PUBLIC_KEY` is a plain (non-secret) constant already set in both `worker/news-proxy.js` and `app.js` — **if it's ever regenerated, it must be updated in both places identically**. The Web Push payload encryption (RFC 8291) and VAPID JWT signing (RFC 8292) are hand-rolled using the Workers runtime's built-in Web Crypto API (`crypto.subtle`) — there's no Node/npm here to use the standard `web-push` library, so if `/push/test` or earnings reminders ever stop delivering, suspect that hand-rolled crypto first (HKDF is implemented manually over HMAC-SHA256, not WebCrypto's combined `'HKDF'` algorithm) rather than assuming it's a simple config issue. A Cron Trigger (Settings > Triggers, e.g. `0 13 * * *` for ~8am ET) must also be added for the `scheduled()` export to actually run on its own — without one, the earnings-check logic exists but nothing ever calls it automatically (the `/push/test` endpoint still works regardless, since it's triggered by an explicit request, not the cron).
  - All restricted via CORS to the GitHub Pages origin.
  - **Important**: this Worker is NOT auto-deployed from git — whenever `worker/news-proxy.js` changes in the repo, Theo has to manually copy-paste the new code into the Cloudflare dashboard's "Edit code" view and click Deploy again. No GitHub Actions / Wrangler CI is set up for it (no Node/npm on this Mac, so Wrangler CLI isn't available — dashboard paste-and-deploy is the working method for now).
- **Stock detail page** (the full-page overlay, `editOverlay` in index.html / `openEditOverlayForLi()` in app.js): opened by tapping a row's edit icon in Manage, a watchlist row's chevron, or any ticker-tape chip on the Portfolio/Watchlist tabs (`openStockDetailBySymbol()`). Shows: a historical chart with 1D/5D/3M/6M/1Y/ALL range tabs (hand-rolled inline SVG polyline, no charting library — `drawChart()`), the existing "Today's Move" AI summary, a **"My Research"** free-text notes section (Theo's own notes per symbol, saved to `localStorage` key `daybook_research_notes`, keyed by ticker — nothing sent anywhere, purely local), and for portfolio positions the existing shares/invested/type edit fields. The whole overlay now scrolls (`overflow-y:auto` with a sticky header) since it no longer fits one screen.
- **Portfolio/watchlist persistence**: previously the DOM was the only copy of this data — reloading the page silently lost any add/edit/remove. Now saved to `localStorage` (`daybook_portfolio_state_v1`, `daybook_watchlist_state_v1`) and rehydrated on load (`hydratePortfolioFromStorage()`/`hydrateWatchlistFromStorage()` in app.js). Persists shares/invested/type/price/chg and the per-symbol news-match keyword. This is per-browser/device only — there's no account system, so nothing syncs across devices. The hardcoded rows in index.html now only matter for the very first visit (before anything's been saved); every reload after that reflects what's actually in `localStorage`.
- **Ticker-tape chips** on the Portfolio and Watchlist tabs were pure static mock HTML with no connection to real holdings. Now rendered dynamically from the real list rows (`syncAllTickerTapes()`, called after every add/edit/remove/quote-refresh) and each chip opens that stock's detail page, same as tapping the row in Manage. The Markets tab's index ticker (S&P 500/DOW/etc.) is untouched — those aren't stocks, so they stay static/non-clickable.
- Dow Jones' public WSJ RSS feeds (`feeds.a.dj.com`) are dead — every endpoint tested returns content frozen at January 2025 (re-verified once, still dead). Reuters discontinued its public RSS feeds entirely a few years back, and Yahoo Finance never had an official API (every endpoint tested 404/400). None of the three are included as real news sources; NYT, MarketWatch, CNBC, Bloomberg, and Financial Times are the five confirmed-working feeds.

## Decisions made
- "Navy football" / earlier "Navy Gold" turned out to mean the US Naval Academy (Navy Midshipmen) colors — but current direction reverted the main content area back to white/black/crimson, with gold reserved narrowly for news-outlet byline text only. Masthead/tab bar remain navy; the index ticker stays its own near-black "Bloomberg terminal" styling (intentional contrast, separate from the rest of the palette).
- Hub model confirmed: news items and podcasts are short summary + link-out only, never full article text or in-app audio playback. This meaningfully reduces the earlier copyright/licensing concern — this is closer to an RSS reader than a republisher.
- Podcast cards link out, never play in-app — consistent with the hub model and with the fact Spotify's API can't stream audio in a third-party app anyway. Default (Spotify not connected) is a real curated list of 7 shows, each show's latest episode fetched directly from the browser via Apple's iTunes lookup API (see Hosting / infrastructure for why this isn't routed through the Worker): In Good Company, Wall Street Breakfast, Goldman Sachs Exchanges, WSJ Tech News Briefing, Odd Lots, Planet Money, Motley Fool Money — all individually verified live with curl before adding. Real connected Spotify data (once set up) takes priority over this list automatically.
- Portfolio holdings are manually editable (shares + dollar amount invested, via an inline edit toggle per row). No brokerage account linking (e.g. Schwab) — confirmed manual entry is sufficient.
- Added a Calendar view (month grid + upcoming events list) reachable from the masthead icon (replaced the old shortcut to Manage). Shows earnings calls/investor events for portfolio + watchlist tickers.
- Bottom tab bar is icon-only, no text labels; active tab shows a solid crimson square highlight behind the icon (not a top bar indicator, not rounded — a rounded-top version was tried and reverted per feedback). The tab bar has a small reserved navy strip below the icons for the iPhone home-indicator safe area — a version that made that strip's color bleed seamlessly into the active highlight was also tried and reverted back to the plain version; don't redo that without being asked again.
- Connectors (Manage tab) lists only sources actually wired up: The New York Times, MarketWatch, CNBC (news), Finnhub (market data), Podcast Feeds (the curated RSS list), and Spotify (real dynamic status). Previously listed WSJ, Yahoo Finance, Reuters, Bloomberg, and Financial Times — all removed since none of them are real/used (WSJ/Reuters/Yahoo Finance have no working feed at all; Bloomberg/FT were always just decorative mockup filler). The toggle buttons remain cosmetic for everything except Spotify — flipping one doesn't actually change what the Worker fetches.
- Chose PWA over native (Swift/SwiftUI) specifically to avoid Apple Developer account cost/overhead. This did mean no background refresh while the app is closed (still true — prices/news only update when opened), but push notifications turned out to still be possible: iOS 16.4+ supports real Web Push for installed home-screen PWAs, which is what the earnings-reminder feature uses.
- Notifications scope: Theo chose "earnings calls coming up" as the first (and so far only) trigger, out of earnings/big-price-move/breaking-news options offered. Reminder fires once per symbol per earnings date, the day before and the day of (whichever the daily cron catches first).

## Guidance given
- **Live price updates**: recommended polling a market-data API on an interval (e.g. every 15–60s while the app is open) rather than a persistent websocket/streaming connection — simpler, cheaper, and plenty for a single-user personal app. True real-time (sub-second) streaming (Polygon.io, Finnhub) is overkill here and often costs more; also note most free-tier market data is 15-minute delayed unless paying for a real-time add-on.

## Open questions / roadblocks
- Portfolio/Watchlist news now comes primarily from Finnhub's `/company-news` (real per-company articles), with the old general-pool name-matching (`NAME_HINTS`) as a fallback only. The fallback still has the same heuristic imprecision as before for whatever thin slice of cases reach it — worth knowing if a mid/small-cap news tab ever looks oddly matched, check whether it's running on the Finnhub path or the fallback path first.
- `NAME_HINTS` (app.js) is pre-populated for the original 11 tickers; any new symbol added through the form now gets a real name from Finnhub plus an auto-derived short match keyword (strips "Inc"/"Corp"/etc. suffixes, takes the first word) rather than falling back to the bare ticker — this was a real bug, fixed. The auto-derived keyword is a blunter heuristic than the curated ones though (e.g. an ETF/fund named after its issuer, like "Vanguard ..." or "Fidelity ...", will match on the issuer's name broadly, same imprecision already flagged above for VOO/FXAIX).
- Spotify OAuth is coded but inert until Theo registers the Spotify Developer app and the Client ID/Secret get filled in (see Hosting / infrastructure). Until then the connector card correctly shows "Not connected" and the placeholder monogram cards stay up — this is honest, not broken.
- News sources: no real technical ceiling on how many could be added (Workers free tier handles far more subrequests than we use), the actual constraint is finding outlets that still run a live public RSS feed — verify each candidate (curl + check the pubDate is current) before adding, the way WSJ/Reuters/Yahoo Finance were ruled out.
