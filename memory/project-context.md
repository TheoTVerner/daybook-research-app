# Project Context

## Scope
Mobile app ("Daybook"): 4 bottom-tab research app — Markets, Portfolio, Watchlist, Manage — plus a Calendar quick-link from the masthead. **Now a real installable PWA**, not just a mockup: live at https://theotverner.github.io/daybook-research-app/, installable via Safari → Share → Add to Home Screen on iPhone. News, portfolio/watchlist prices + day change, "why is it moving," and the Calendar's earnings dates are all real and dynamic (update automatically as tickers are added/removed) — see Hosting / infrastructure for the backend details. Spotify OAuth is built but **pending Theo registering a Spotify Developer app** — see that section for exactly what's needed.

**Personal use only.** Theo confirmed this app is for himself and will not be published/distributed to anyone else. This meaningfully changes the risk profile: no app-store review process, no multi-user privacy law exposure (GDPR/CCPA etc. are triggered by processing *other people's* data, not your own), no need to worry about terms-of-service clauses aimed at commercial/public redistribution. Don't over-apply general regulatory caution that's really aimed at public products — but revisit this if Theo ever considers sharing or publishing it.

## Hosting / infrastructure
- **Repo**: github.com/TheoTVerner/daybook-research-app (public, main branch, served via GitHub Pages from branch root)
- **Live URL**: https://theotverner.github.io/daybook-research-app/
- **Local project folder**: `~/Desktop/Theo's Research App` — this *is* the git repo; working directly in it pushes straight to the live site (`git push` after committing updates to main)
- **SSH auth**: a dedicated deploy key was generated at `~/.ssh/id_ed25519_daybook`, registered in `~/.ssh/config` for github.com, and added to macOS Keychain — the public half is on Theo's GitHub account's SSH keys. No GitHub CLI (`gh`) or Homebrew installed on this Mac; Xcode Command Line Tools were installed mid-session to get `git` working.
- App structure: `index.html` / `styles.css` / `app.js` (plain, no build step, no framework) + `manifest.json` + `sw.js` (basic app-shell service worker) + `icons/` (generated locally via Pillow, not hand-designed).
- To ship an update: edit the files, `git add -A && git commit -m "..." && git push` from the project folder — GitHub Pages rebuilds automatically in under a minute, and the installed home-screen app picks up changes next time Theo opens it (no reinstall needed). Note GitHub Pages serves everything with `Cache-Control: max-age=600` — when verifying a just-shipped change, bypass with a cache-busting query string (`?t=...`) rather than assuming it's broken.
- **Backend**: one Cloudflare Worker at `worker/news-proxy.js` in the repo, deployed manually (Cloudflare account under Theo's login, Worker named `daybook-research`, URL `https://daybook-research.ttverner.workers.dev/`). Three routes in the same Worker:
  - `GET /` — NYT/MarketWatch/CNBC RSS fetched server-side (CORS blocks browsers from doing this directly), returned as clean JSON.
  - `GET /quotes?symbols=AAPL,MSFT` — real price + day change via Finnhub's free tier (needs the Cloudflare secret `FINNHUB_API_KEY`, a free key from finnhub.io, set in Worker Settings > Variables and Secrets).
  - `GET /explain?symbol=NVDA&name=Nvidia` — a "why is it moving" summary via **Cloudflare Workers AI** (free tier, needs an `AI` binding added in Worker Settings > Bindings — no separate account, it's built into Cloudflare). Only summarizes when real headlines actually mention the company; otherwise says so rather than letting the model invent a reason. Model used: `@cf/meta/llama-3.2-3b-instruct` (Cloudflare's catalog specifically calls this one out as suited to summarization). **Note**: Workers AI model IDs get deprecated over time (already hit this once — `llama-3.1-8b-instruct` was deprecated 2026-05-30) — if `/explain` ever silently falls back to "couldn't reach the summarizer," check the model ID against Cloudflare's current catalog (developers.cloudflare.com/workers-ai/models/) before assuming it's a code bug.
  - `GET /quotes` also fetches each symbol's real company name via Finnhub's `profile2` endpoint. Known gap: `profile2` doesn't cover ETFs/mutual funds well — VOO's name comes back null (price still works), and FXAIX returns null entirely (Finnhub's free-tier quote endpoint doesn't cover mutual fund NAV pricing at all, so FXAIX silently keeps showing its original hardcoded mock price). A mutual-fund-specific data source (e.g. Alpha Vantage covers some funds) would be the fix if that's worth doing.
  - `GET /earnings?symbols=AAPL,MSFT` — each symbol's next real earnings-call date via Finnhub's earnings calendar endpoint, scoped to a ~5-month forward window (quarterly cadence reliably catches the next one). Powers the Calendar tab, which is now fully dynamic: `buildCalendar()` re-fetches every time a ticker is added or removed from Portfolio/Watchlist (via the add form, watchlist remove button, or Remove from Portfolio/Watchlist in the detail overlay) — never a fixed/hardcoded ticker list.
  - `POST /spotify/token` {code, redirect_uri} and `GET /spotify/shows?refresh_token=...` — real Spotify OAuth. **Not live yet** — needs a Spotify Developer app registered at developer.spotify.com/dashboard, with its exact redirect URI set to `https://theotverner.github.io/daybook-research-app/`. Once registered: give Claude the Client ID (not secret, safe to share — it needs updating in both `worker/news-proxy.js`'s `SPOTIFY_CLIENT_ID` constant and `app.js`'s `SPOTIFY_CLIENT_ID` constant, currently both placeholder strings), and set the Client Secret as a new Cloudflare secret named `SPOTIFY_CLIENT_SECRET` (Theo does this directly in the dashboard, never shared in chat — same pattern as `FINNHUB_API_KEY`). Flow: tapping Connect on the Spotify connector card sends the browser to Spotify's real login/consent screen (scope `user-library-read`), Spotify redirects back with a code, the Worker exchanges it for tokens, and the refresh token is stored in the browser's `localStorage` (key `daybook_spotify_refresh_token`) so Theo doesn't have to re-login each time. Once connected, real cover art + latest-episode titles replace the placeholder monogram cards (this app isn't sandboxed like an Artifact, so real `<img>` tags from Spotify's CDN work fine, no CSP restriction).
  - All restricted via CORS to the GitHub Pages origin.
  - **Important**: this Worker is NOT auto-deployed from git — whenever `worker/news-proxy.js` changes in the repo, Theo has to manually copy-paste the new code into the Cloudflare dashboard's "Edit code" view and click Deploy again. No GitHub Actions / Wrangler CI is set up for it (no Node/npm on this Mac, so Wrangler CLI isn't available — dashboard paste-and-deploy is the working method for now).
- Dow Jones' public WSJ RSS feeds (`feeds.a.dj.com`) are dead — every endpoint tested returns content frozen at January 2025. Reuters discontinued its public RSS feeds entirely a few years back, and Yahoo Finance never had an official API. None of the three are included as real news sources; NYT, MarketWatch, and CNBC are the three confirmed-working feeds.

## Decisions made
- "Navy football" / earlier "Navy Gold" turned out to mean the US Naval Academy (Navy Midshipmen) colors — but current direction reverted the main content area back to white/black/crimson, with gold reserved narrowly for news-outlet byline text only. Masthead/tab bar remain navy; the index ticker stays its own near-black "Bloomberg terminal" styling (intentional contrast, separate from the rest of the palette).
- Hub model confirmed: news items and podcasts are short summary + link-out only, never full article text or in-app audio playback. This meaningfully reduces the earlier copyright/licensing concern — this is closer to an RSS reader than a republisher.
- Podcast cards link out to Spotify (no fake in-app play button) — consistent with the hub model and with the fact Spotify's API can't stream audio in a third-party app anyway. Podcast art is a generated monogram placeholder (no real cover art pulled yet).
- Portfolio holdings are manually editable (shares + dollar amount invested, via an inline edit toggle per row). No brokerage account linking (e.g. Schwab) — confirmed manual entry is sufficient.
- Added a Calendar view (month grid + upcoming events list) reachable from the masthead icon (replaced the old shortcut to Manage). Shows earnings calls/investor events for portfolio + watchlist tickers.
- Bottom tab bar is icon-only, no text labels; active tab shows a red rounded highlight behind the icon (not a top bar indicator).
- Chose PWA over native (Swift/SwiftUI) specifically to avoid Apple Developer account cost/overhead, at the cost of no true background refresh or push notifications while the app is closed.

## Guidance given
- **Live price updates**: recommended polling a market-data API on an interval (e.g. every 15–60s while the app is open) rather than a persistent websocket/streaming connection — simpler, cheaper, and plenty for a single-user personal app. True real-time (sub-second) streaming (Polygon.io, Finnhub) is overkill here and often costs more; also note most free-tier market data is 15-minute delayed unless paying for a real-time add-on.

## Open questions / roadblocks
- Portfolio/Watchlist news (and the "why is it moving" explain feature) are filtered from the same general NYT/MarketWatch/CNBC pool by simple company-name string matching (e.g. "Nvidia" for NVDA, via the `NAME_HINTS` map in app.js, reused server-side in the Worker) — flagged as a heuristic. General market feeds rarely cover individual mid/small caps (PLTR, SOFI, COIN) or funds (FXAIX, VOO), so those often come back empty/"no headlines found" rather than wrong. A real per-ticker news source (e.g. a paid news API with symbol filtering) would be the next step if that's worth fixing.
- `NAME_HINTS` (app.js) is pre-populated for the original 11 tickers; any new symbol added through the form now gets a real name from Finnhub plus an auto-derived short match keyword (strips "Inc"/"Corp"/etc. suffixes, takes the first word) rather than falling back to the bare ticker — this was a real bug, fixed. The auto-derived keyword is a blunter heuristic than the curated ones though (e.g. an ETF/fund named after its issuer, like "Vanguard ..." or "Fidelity ...", will match on the issuer's name broadly, same imprecision already flagged above for VOO/FXAIX).
- Spotify OAuth is coded but inert until Theo registers the Spotify Developer app and the Client ID/Secret get filled in (see Hosting / infrastructure). Until then the connector card correctly shows "Not connected" and the placeholder monogram cards stay up — this is honest, not broken.
- News sources: no real technical ceiling on how many could be added (Workers free tier handles far more subrequests than we use), the actual constraint is finding outlets that still run a live public RSS feed — verify each candidate (curl + check the pubDate is current) before adding, the way WSJ/Reuters/Yahoo Finance were ruled out.
